# Оценка качества

## Правила

- Реальные корпоративные звонки не используются.
- Каждый файл должен иметь источник/способ генерации и эталон, составленный до инференса.
- Функциональный тест без надёжного эталона не считается quality-тестом.
- WER приводится вместе с конкретными заменами, удалениями и вставками.
- Отдельно вручную оцениваются числа, даты, реквизиты, специальные термины, пропущенные фразы и добавленные слова.
- TTS полезен для воспроизводимости, но не заменяет естественные мужские/женские телефонные разговоры с шумом и перебиваниями.

## Функциональный открытый файл upstream

`test_call.flac` — копия `tone/demo/audio_examples/audio_short.flac` из официального репозитория T-one commit `3c5b6c0`; SHA-256 `2fdcdd574f4e0d651e1ac70710d2eba50299789d3b8279458c019ec829434afe`.

Greedy-результат:

> ну сейчас к тебе приедет бригада давай давай я жду

Файл успешно доказал декодирование FLAC, локальный инференс, сегменты и JSON, но не используется для расчёта качества: рядом с бинарным файлом нет отдельного эталона, а пример текста в текущем README/model card не совпадает с фактическим greedy-результатом. Нельзя определить, является ли это ошибкой документации, сменой примера или качеством decoder-а без ручной разметки.

## Синтетический набор

### `1001.wav`

- источник: системный офлайн TTS `say`, голос Milena (`ru_RU`);
- преобразование: test-only `scripts/aiff_to_phone_wav.py`, mono PCM 16-bit 8 кГц (`afconvert` на проверенной macOS завершался с code 139);
- эталон: `tests/fixtures/1001.reference.txt`;
- содержание: БИК, ИНН, НКЦ, расчётный счёт, клиринг, номер договора, сумма и дата;
- SHA-256 WAV: `0c3cb2f3b018a58da0e41c5105fa4124fc4e6f9593c344d4500c7d27c7c4f8a8`;
- фактический формат: mono PCM16 8 кГц, 16,115 с;
- decoder: T-one greedy (beam search ещё не проверен);
- результат: 49 слов против 57 слов нормализованного эталона; 3 замены, 8 удалений, 0 вставок, WER `0,1930`.

Результат модели:

> здравствуйте назовите биклинн и номер договора бик ноль четыре четыре пять два пять два два пять нн семь семь ноль один два три четыре пять шесть семь расчетный счет четыре ноля один клиринг через нкц сумма сто двадцать пять тысяч рублей дата девятое августа две тысячи двадцать шестого года

Конкретные ошибки:

- первая последовательность «бик и эн эн» склеена в `биклинн`;
- вторая «и эн эн» распознана как `нн`;
- союз «и» пропущен в «четыре ноля и один»;
- «эн ка цэ» склеено в `нкц`;
- все произнесённые цифры БИК и ИНН сохранены в правильном порядке;
- «номер договора», «расчётный счёт», «клиринг», сумма и дата распознаны по смыслу и по словам без ошибки после нормализации `ё/е`;
- добавленных моделью слов нет;
- вся запись объединена в один сегмент, то есть для этой непрерывной TTS-речи фразовые границы практически отсутствуют.

Вывод ограничен этим файлом: greedy сохраняет содержание и числа TTS-примера, но неудовлетворительно форматирует буквенные аббревиатуры. Нужен beam-search и естественная речь до решения о качестве.

## Не выполнено

Естественная мужская и женская речь, быстрый диалог, паузы, перебивания, шумы, фамилии и организации. Для них нужен открытый лицензированный или специально записанный набор с согласием участников и ручной разметкой.
