# Модель безопасности

## Обязательные свойства

- ASR работает локально; внешние сетевые обращения во время обработки запрещены.
- Промышленный сервер должен работать без свободного исходящего интернета. Разрешающий список, если вообще нужен для эксплуатации, не должен включать произвольный HTTP(S), DNS через внешние резолверы или прокси.
- Модель и зависимости переносятся через проверенный внутренний источник.
- Для исходного кода, пакетов и весов фиксируются версия, источник, лицензия и SHA-256.
- Runtime принимает только существующий локальный путь модели; удалённые model ID и fallback на скачивание запрещены.
- Аудио и транскрипции хранятся внутри корпоративного контура.
- Исходный `raw_text` и очищенный `text` равно считаются транскрипцией звонка и имеют одинаковые ограничения доступа и хранения.
- Markdown содержит полный текст и имеет те же права доступа и срок хранения, что аудио и JSON.
- Перенос в папку звонка не перекодирует и не перезаписывает аудио; коллизия имени завершается ошибкой.
- Временные JSON whisper.cpp и PCM WAV для AAC создаются только в scratch-подкаталоге результата и удаляются при завершении; исходное аудио остаётся неизменным.
- Постобработка на MVP только детерминированная; внешние или локальные LLM в runtime не подключены.
- Reference HTTP API слушает только `127.0.0.1`; открывать его в LAN/интернет без корпоративного ingress, service-auth, TLS и ACL запрещено.
- HTTP-загрузка требует `Content-Length`, ограничивает размер, пишет во временный файл и атомарно публикует его без перезаписи занятого `call_id`.
- Права сервисной учётной записи минимальны: чтение и перенос стабильного входа в папку звонка, создание результата и технического состояния; содержимое аудио не изменяется, а из архива оно автоматически не удаляется.
- Логи содержат идентификатор задачи, статус, длительности и класс ошибки, но не полный текст, аудиобайты, токены или секреты.

## Угрозы и меры

| Угроза | Базовая мера |
|---|---|
| Скрытая выгрузка данных зависимостью | pin/hash, аудит кода, deny-by-default egress, наблюдение трафика |
| Нативный декодер недоверенного AAC | hash-pinned PyAV wheel, только local regular-file path, лимиты ресурсов, SCA/CVE до production |
| Автоскачивание модели | локальный adapter, offline-флаги библиотек, отсутствие egress, тест пустого кэша |
| Подмена весов | внутренний реестр, SHA-256, read-only каталог в runtime |
| Path traversal через `call_id` | строгий разбор basename и допустимых символов, независимый заданный output path |
| Несанкционированная HTTP-загрузка/чтение | reference server только на loopback; production требует внешний mTLS/service-auth ingress и ACL |
| Перезапись звонка повторным `PUT` | проверка всех форматов того же `call_id` и exclusive публикация без overwrite |
| Неполная/чрезмерная HTTP-загрузка | обязательный `Content-Length`, лимит, streaming в hidden temp, `fsync`, удаление temp при ошибке |
| Частично записанный файл | проверка стабильного размера/mtime и успешного открытия до очереди |
| Повторная/двойная обработка | уникальный ключ и lease-транзакция SQLite, атомарный output |
| Раскрытие через логи/ошибки | структурированные сообщения без transcript, ограничение traceback в production |
| Неограниченный расход ресурсов | лимит размера/длительности, bounded queue и ограниченная параллельность |

## Проверка сетевого поведения

Офлайн-повтор — необходимая, но недостаточная проверка. План проверки:

1. Подготовить зависимости и веса в контролируемой staging-среде.
2. Очистить/изолировать пользовательские кэши, чтобы тест не скрывал неявную зависимость от сети.
3. Запустить сервис в отдельном network namespace или контейнере без сети.
4. Повторить тот же искусственный файл после полного перезапуска процесса.
5. Параллельно наблюдать DNS и соединения: `tcpdump`, Wireshark, eBPF/audit-средства или корпоративный NDR.
6. Повторить с firewall deny-all egress и журналированием блокировок.
7. Проверить отсутствие обращений не только при успехе, но и при ошибке/отсутствующей модели.

Пример для Linux должен быть адаптирован безопасниками к среде: отдельный namespace без интерфейса либо firewall-правило deny-all для UID сервиса, плюс `tcpdump -i any`. На macOS возможны отдельный sandbox/VM и Packet Filter. Конкретные команды не фиксируются до выбора промышленной ОС.

Для проверенной Windows dev/pilot-среды добавлен `security/windows-deny-network.ps1`: после сетевого staging администратор создаёт отдельные outbound-block правила для фактического Python (`.poetry-cache\venv\Scripts\python.exe` в архивном запуске либо `.venv\Scripts\python.exe` в ручной dev-установке) и нативного `whisper-cli.exe`. One-click запуск требует успешной установки этих правил до worker. Это защита dev/pilot-хоста, а не замена корпоративной WFP/EDR/NDR-политики.

## Хранение, доступ, удаление

Политика пока не определена владельцами системы. До согласования:

- не копировать данные в общие временные каталоги;
- не включать исходники и результаты в резервные копии разработки;
- ограничить доступ сервисной учётной записью и группой CRM;
- удаление результатов не реализовывать автоматически;
- срок хранения, юридические основания, аудит доступа, backup и безопасное удаление согласовать отдельно.

## Ограничение вывода

Этот документ не является полноценным аудитом безопасности и не утверждает безопасность T-one или whisper.cpp. Итог требует анализа конкретных версий, SBOM/уязвимостей, конфигурации ОС, прав, сети и фактического runtime-трафика.
