# Промежуточные результаты производительности

## Среда

- MacBook Air, Intel Core i5 1,6 ГГц, 2 физических ядра/Hyper-Threading;
- RAM 8 ГБ;
- macOS 14.1.1 x86_64;
- Python 3.12.13;
- T-one code `3c5b6c015038173840e62cea99e10cdb1c759116`;
- model revision `106f3b0b32a9e107eb613312e4ebc61ff3d53926`;
- ONNX Runtime 1.22.0 CPU, decoder greedy;
- GPU не использовался;
- worker измеряет CPU time и peak RSS через `resource.getrusage()`; на первой
  серии эти метрики ещё не были включены.

## Одиночные cold-process тесты

| Файл | Формат | Длительность, с | Полное время CLI, с | RTF |
|---|---|---:|---:|---:|
| `test_call.flac` | FLAC, декодируется в mono 8 кГц | 6,360 | 11,532 | 1,8132 |
| `1001.wav` | mono PCM16 8 кГц | 16,115 | 73,034 | 4,5321 |
| `1001_offline.wav` | тот же PCM, OS `deny network*`, прогретые кэши | 16,115 | 9,430 | 0,5852 |
| `1002.wav` через worker | тот же PCM, прогретые модель/кэши | 16,115 | 8,399 | 0,5212 |

`processing_seconds` включает import/model load, decode и inference, но не включает последующую оценку WER. Разброс RTF очень велик; одиночных измерений недостаточно для модели производительности. Возможны page cache/model warm-up, thermal throttling и фоновые нагрузки. Multi-file throughput приведён ниже отдельно.

## Ограниченный вывод

- cold/нагруженный запуск был медленнее реального времени, прогретые повторы — быстрее;
- хост ниже upstream-рекомендации по CPU;
- запуск параллельности 2/4/8 и 100 файлов сейчас не обоснован;
- размер/скорость beam-search с 5,46-ГБ KenLM не измерены;
- production sizing по этим данным делать нельзя.

Следующий performance-шаг — повторить один и десять файлов на целевой Linux CPU/GPU-машине с отдельным измерением model-load, RSS, CPU и устойчивого worker RTF, затем безопасно проверить параллельность 2/4 и очередь из 100 реальных ASR-задач.

## Десять файлов последовательно, один worker

Использованы десять идентичных копий искусственного `1001.wav`; это измеряет throughput, но не разнообразие длительностей/кодеков.

| Batch | Файлов | Общая длительность, с | Wall time, с | Сумма processing, с | Средний RTF | Диапазон RTF | Peak RSS | Ошибки |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `2000–2009` | 10 | 161,150 | 58,680 | 58,123 | 0,3607 | 0,3246–0,5500 | не получен | 0 |
| `2010–2019` | 10 | 161,150 | 183,829 | 183,460 | 1,1384 | 0,5731–1,2991 | 313,1 МБ | 0 |

Во втором batch CPU time составил 244,268 с, то есть около 132,9% одного логического CPU по шкале macOS. Первый `/usr/bin/time -l` не смог прочитать служебный `sysctl` внутри sandbox, поэтому его peak RSS не заявляется; сам worker завершил все 10 задач.

Разница почти в 3,1 раза на идентичном входе показывает, что ноутбук занят фоновой нагрузкой/thermal effects и непригоден для достоверного capacity planning. Для этого хоста рекомендуемая параллельность MVP — **1**. Параллельность 2/4/8 и 100 ASR-файлов не запускаются до выделенной тестовой машины; это осознанное ограничение, а не пропущенный успешный результат.

## Windows 10 / CPython 3.11.9

Проверенный хост: Windows 10.0.19045 x64, 16 логических процессоров, ONNX Runtime 1.22.0 CPU, decoder greedy. RAM не удалось прочитать из ограниченной среды; GPU не использовался.

| Сценарий | Аудио, с | Processing, с | RTF |
|---|---:|---:|---:|
| `1001.wav`, новый CLI, hash модели включён | 16,115 | 3,577 | 0,2219 |
| `test_call.flac`, новый CLI | 6,360 | 2,649 | 0,4165 |
| `test_call.flac`, наблюдение сети | 6,360 | 2,467 | 0,3879 |

Один worker последовательно обработал три копии синтетического `1001.wav` за 6,894 с wall time. Первый файл занял 3,485 с (`RTF 0,2163`), следующие — 1,698 и 1,672 с (`RTF 0,1054` и `0,1037`). Суммарная длительность аудио — 48,345 с; модель загружалась один раз. CPU time составил 43,188 с, peak RSS на Windows через стандартный модуль `resource` недоступен.

На этом хосте проверенный greedy worker быстрее реального времени, но три одинаковых TTS-файла не являются production sizing или проверкой естественной речи.

## Windows 10 / whisper.cpp large-v3 / RTX 3080 — исторические прогоны до обязательного VAD

Проверено 2026-08-11: Intel Core i9-11900K, 16 логических процессоров, NVIDIA GeForce RTX 3080 10 ГБ, driver 591.74, whisper.cpp v1.9.2 CUDA 12.4 bundle, GGML F16 large-v3, beam size 5.

| Сценарий | Аудио, с | Processing, с | RTF |
|---|---:|---:|---:|
| `1001.wav`, без prompt | 16,115 | 4,579 | 0,2841 |
| `1001.wav`, UTF-8 prompt терминов | 16,115 | 4,162 | 0,2583 |
| `test_call.flac`, одиночный CLI | 6,360 | 3,410 | 0,5362 |
| `test_call.flac`, SQLite-worker | 6,360 | 3,320 | 0,5220 |

Все четыре запуска завершены на локальных артефактах, но измерены 2026-08-11 до обязательного Silero VAD и не описывают поставляемую конфигурацию. Это функциональное измерение двух коротких файлов, не capacity planning. Печатный `cpu_seconds` worker-а учитывает только родительский Python-процесс и не включает нативный whisper.cpp subprocess; для sizing нужна отдельная OS/GPU-телеметрия.

Текущая конфигурация Whisper+VAD 2026-08-14 обработала шесть коротких FLEURS-файлов: 84,96 с аудио за 21,203 с, взвешенный `RTF 0,2496`, диапазон по файлам `0,1824–0,3980`. Этот regression-прогон подтверждает работу быстрее реального времени на данной малой выборке, но не sustained throughput.
