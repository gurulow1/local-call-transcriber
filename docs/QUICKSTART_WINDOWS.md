# Быстрый запуск пилота на Windows

Эта инструкция предназначена для контролируемой демонстрации на Windows 10/11 x64. До прохождения security acceptance gate используйте только открытые, искусственные или самостоятельно записанные тестовые данные без корпоративной информации.

## Что понадобится

- распакованный архив проекта в папке с правом записи;
- свободное место на диске: для NVIDIA-пути первый запуск загружает около 3,8 ГБ runtime и модели, дополнительно нужно место для окружения и результатов;
- интернет только для первой staging-фазы;
- для основного quality-пути — совместимая NVIDIA GPU и установленный драйвер;
- имя тестового файла из ASCII-букв, цифр, `_` или `-`, например `demo-001.wav`.

Поддерживаемые расширения: `.wav`, `.mp3`, `.flac`, `.ogg`, `.aac` (AAC ADTS). Не используйте пробелы, кириллицу и повтор уже занятого `call_id` в имени демонстрационного файла.

Технические guards пилота: не более четырёх часов декодированного аудио; reference HTTP API принимает до 1 ГиБ на upload по умолчанию. Это защитные пределы, а не утверждённые бизнес-лимиты.

## Первый запуск

1. Дважды нажмите `Запустить транскрибатор.cmd`.
2. Не закрывайте окно. Запускатор создаёт локальное окружение, загружает и проверяет runtime и модель. При доступной NVIDIA выбирается Whisper large-v3/CUDA, иначе — T-one/CPU.
3. Подтвердите стандартный Windows UAC-запрос на создание точных outbound-block правил. При отказе worker намеренно не запустится.
4. Дождитесь сообщения о запуске worker-а и открытого каталога `data/input`.
5. Скопируйте один тестовый аудиофайл, например `demo-001.wav`, в `data/input`.
6. Оставьте файл неизменным минимум на пять секунд. После обработки откройте:

```text
data/calls/demo-001/
  demo-001.wav
  demo-001.json
  demo-001.md
```

Первый запуск не следует проводить во время показа: загрузки велики и зависят от сети. Для демонстрации заранее выполните staging и контрольную обработку на том же хосте.

One-click сам запрашивает административное подтверждение после staging. Для ручной установки те же точные правила применяются из PowerShell от имени администратора:

```powershell
powershell -ExecutionPolicy Bypass -File security\windows-deny-network.ps1
```

Затем запустите `Проверить готовность.cmd`. До тех пор, пока он печатает `NO-GO`, показ не начинайте. Проверка не создаёт firewall rules сама: она без UAC подтверждает уже применённые правила, hashes, runtime, GPU и каталоги.

## Как читать результат

`demo-001.md` — человеческий отчёт:

- ссылка на исходное аудио;
- длительность, модель и decoder;
- полный очищенный текст;
- фрагменты с таймкодами;
- предупреждение о ручной проверке критичных данных.

`demo-001.json` — машинный результат по схеме `1.2`:

- `status`, `call_id`, длительность, processing time и RTF;
- модель, revision и decoder; для Whisper также имя, revision, SHA-256 и порог VAD;
- `text` после детерминированной постобработки;
- `raw_text` и `segments[].asr_text` без потери исходной выдачи ASR;
- сегменты с `start`/`end`;
- структурированная ошибка при неуспехе.

Markdown и JSON содержат полную транскрипцию и должны иметь те же права доступа и срок хранения, что аудио.

## Повторный запуск

Повторно нажмите `Запустить транскрибатор.cmd`: при целых локальных артефактах staging не повторяется. Worker продолжает следить за `data/input`. Чтобы остановить его, нажмите `Ctrl+C` в окне.

Завершённый `call_id` не обрабатывается повторно и не перезаписывается. Для нового показа используйте новое имя, например `demo-002.wav`. Failed-задачу повторяют только явной административной операцией после диагностики причины.

## Если результата нет

1. Проверьте, что расширение поддерживается, а имя соответствует правилу `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`.
2. Не перемещайте и не изменяйте файл во время обработки.
3. Проверьте `data/failed/{call_id}.json` для задачи очереди либо `data/failed/rejected-*.json` для неподдерживаемого расширения/небезопасного имени.
4. Проверьте технические журналы `logs/worker.log` и `logs/setup.log`. Они не должны содержать текст записи.
5. Не удаляйте и не изменяйте исходное аудио при диагностике.

Подробная инженерная процедура находится в [INSTALLATION.md](INSTALLATION.md), ограничения безопасности — в [SECURITY.md](SECURITY.md), состояние качества — в [QUALITY_EVALUATION.md](QUALITY_EVALUATION.md), сводка для пилота — в [PILOT_REPORT.md](PILOT_REPORT.md).

## Go / no-go перед демонстрацией

- [ ] staging заранее завершён на том же Windows-хосте;
- [ ] контрольный открытый/искусственный файл создаёт JSON `1.2` и Markdown;
- [ ] выбранный пример не содержит корпоративных данных;
- [ ] в `data/input` нет старых конфликтующих файлов;
- [ ] используется новый безопасный `call_id`;
- [ ] докладчик готов показать ограничение на критичных реквизитах;
- [ ] VAD regression и валидность таймкодов пройдены; точность границ и тихая телефонная речь не называются подтверждёнными.

Для обработки конфиденциальных данных дополнительно требуется пройденный security gate: утверждённый OS-level deny-all egress для фактических Python и нативного ASR-процессов, наблюдение DNS/соединений, проверка hashes и review точного runtime bundle. Сам по себе успешный локальный запуск этого не доказывает.
