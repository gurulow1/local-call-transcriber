# Аудит T-one

> Этот аудит фиксирует первоначальный выбор на 2026-08-09. После фактической оценки качества основной Windows/NVIDIA-путь изменён на whisper.cpp/large-v3 в ADR-011; T-one сохранён как fallback.

## Объект и границы проверки

- официальный код: `https://github.com/voicekit-team/T-one`;
- проверенный commit: `3c5b6c015038173840e62cea99e10cdb1c759116` от 2025-12-30;
- версия пакета: `tone 0.1.0` (`pyproject.toml:2-3`);
- официальный репозиторий весов: `https://huggingface.co/t-tech/T-one`;
- проверенная revision весов: `106f3b0b32a9e107eb613312e4ebc61ff3d53926` от 2025-07-30;
- дата аудита: 2026-08-09;
- выполнен статический аудит репозитория и публичных метаданных модели; установка, SCA/CVE scan и runtime-трассировка сети ещё не выполнены.

Open source не считается доказательством безопасности. Выводы ниже ограничены указанными версиями и должны дополняться контролем сборки, зависимостей, ОС, сети и фактического трафика.

## Краткий вывод

T-one пригоден для следующего шага MVP, потому что имеет явный локальный конструктор `StreamingCTCPipeline.from_local()` (`tone/pipeline.py:87-99`). Runtime прототипа не должен вызывать `from_hugging_face()` и не должен использовать demo/готовый Docker-образ.

Два обязательных артефакта для beam search:

| Файл | Размер источника | SHA-256 источника |
|---|---:|---|
| `model.onnx` | 144 193 371 байт | `707e4a282d5036304a0b8603ad83945840c3075f53c49911ef88c19bcc5a7d52` |
| `kenlm.bin` | 5 463 477 004 байта | `8c31a489a51a6e9236112dacb6bed12f45e8df734057615fa6bf220a5a769a1d` |

Revision обязательно pin-ить: upstream-функции `hf_hub_download()` не передают `revision` (`tone/onnx_wrapper.py:53-63`, `tone/decoder.py:85-95`) и поэтому следуют текущей ветке модели.

## Ответы на контрольные вопросы

### 1. Какая лицензия у кода?

Репозиторий и метаданные заявляют Apache License 2.0. Файл `LICENSE` содержит copyright `2025 T-Software DC` и краткое уведомление/ссылку, но не полный текст Apache-2.0. Для внутренней поставки следует сохранить upstream-уведомление и добавить полный текст лицензии.

### 2. Какая лицензия у весов?

Model card и metadata официального `t-tech/T-one` заявляют Apache-2.0 для предобученных моделей. Отдельного файла `LICENSE` в видимом списке артефактов модели нет. Это не запрещает использование по заявленной лицензии, но происхождение/лицензию следует зафиксировать снимком model card и подтвердить у юридической/закупочной функции.

### 3. Разрешено ли коммерческое и внутреннее использование?

Apache-2.0 в общем случае разрешает использование, воспроизведение, модификацию и распространение, включая коммерческое, при выполнении условий лицензии. Для кода и модели нет заявленного non-commercial ограничения. Это технический вывод, не юридическое заключение; перед production нужна корпоративная проверка также транзитивных лицензий.

### 4. Какие уведомления и лицензии сохранить?

- copyright и лицензионное уведомление T-Software DC;
- полный Apache-2.0 и снимок model card/revision;
- описание внесённых изменений, если распространяется изменённая версия;
- лицензии и third-party notices всех поставляемых колёс/библиотек;
- отдельно обратить внимание на KenLM: большая часть кода заявлена LGPL-2.1-or-later с исключениями по файлам;
- ONNX Runtime поставляет собственный `ThirdPartyNotices.txt`; его нужно брать из точно выбранного релиза;
- `miniaudio`/Python binding заявляет MIT с несколькими copyright holders.

`pyctcdecode`, `huggingface-hub`, ONNX Runtime, NumPy и прочие транзитивные компоненты должны пройти автоматизированный license/SBOM scan точных артефактов. Полный юридический реестр пока не сформирован.

### 5. Что скачивается при установке?

Обычная `poetry install` обращается к настроенным package indexes и получает прямые/транзитивные пакеты. Основные runtime-зависимости из `pyproject.toml`: NumPy, Hugging Face Hub, ONNX Runtime, pyctcdecode и KenLM; extra `demo` добавляет miniaudio, FastAPI и Uvicorn. Lock-файл фиксирует версии и хэши дистрибутивов, однако индекс и артефакты нужно зеркалировать внутри контура.

Upstream Dockerfile дополнительно:

1. получает базовые `python:3.10`/`python:3.10-slim` образы без digest pin;
2. скачивает и исполняет Poetry installer через `curl` без зафиксированного SHA-256 (`Dockerfile:6-7`);
3. устанавливает зависимости;
4. выполняет `python -m tone download /models`, то есть скачивает оба веса с Hugging Face (`Dockerfile:26-28`).

Готовый образ не используется в MVP. Воспроизводимая внутренняя сборка должна pin-ить base digest, wheel hashes и проверенные веса.

### 6. Что скачивается при первом запуске?

- `StreamingCTCPipeline.from_hugging_face()` скачивает/берёт из HF-кэша `model.onnx` и `kenlm.bin`.
- Demo вызывает этот метод, если переменная `LOAD_FROM_FOLDER` не задана (`tone/demo/website.py:44-50`).
- `from_local()` ничего не скачивает по исходному коду и требует локальные `model.onnx`/`kenlm.bin`.
- Web UI ссылается на Bootstrap CSS/JS на `cdn.jsdelivr.net` (`tone/demo/static/index.html:8-9,186`), поэтому браузер demo обращается наружу даже при локальных весах.

Наш runtime всегда вызывает `from_local()` и дополнительно устанавливает offline/telemetry-disable переменные. Отсутствующий локальный артефакт должен давать ошибку, не fallback.

### 7. Выполняются ли внешние запросы во время транскрибации?

В исходниках T-one найдены только явные HF-загрузки через `hf_hub_download()` и внешние ресурсы demo. В пути `from_local()` -> `forward_offline()` прямых HTTP/DNS/socket вызовов нет. Это статическое наблюдение, а не доказательство отсутствия сетевой активности транзитивных бинарных зависимостей. Нужны запуск без сети и захват трафика.

### 8. Можно ли указать строго локальный путь к модели?

Да. `StreamingCTCPipeline.from_local(dir_path)` открывает `${dir_path}/model.onnx` и `${dir_path}/kenlm.bin`. Для greedy decoder нужен только ONNX, но upstream API всё равно импортирует библиотеки decoder-а.

### 9. Можно ли полностью отключить автоматическую загрузку?

На уровне приложения — да: никогда не вызывать `from_hugging_face()`/`download_from_hugging_face()`, проверять локальные файлы до импорта модели, задать `HF_HUB_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1`, `DO_NOT_TRACK=1` и закрыть egress. В самом upstream нет единого флага, удаляющего download-методы; поэтому сетевой deny остаётся обязательным вторым барьером.

### 10. Какие зависимости требуют отдельной проверки?

- **KenLM 0.3.0:** C++/Python сборка, LGPL-2.1-or-later и исключения, платформенная совместимость, mmap большого LM.
- **pyctcdecode 0.5.0:** beam-search код и его транзитивные зависимости.
- **onnxruntime 1.19.2/1.22.0 по маркерам Python:** нативный wheel, execution providers, third-party notices, CVE и потребление потоков/памяти.
- **huggingface-hub 0.33.0, requests, urllib3, hf-xet:** сетевые возможности, telemetry/offline flags; runtime они не нужны для загрузки локального файла, но импортируются upstream.
- **miniaudio 1.61 (demo extra):** нативное декодирование недоверенного аудио; fuzz/CVE и допустимые форматы.
- **PyAV 18.0.0 (optional AAC):** BSD-3-Clause Python wrapper с бундлом FFmpeg; wheel зафиксирован SHA-256, но нужны SCA/CVE и отдельный аудит транзитивных лицензий FFmpeg.
- **NumPy, protobuf, sympy, pyyaml, fsspec и прочие locked packages:** SCA, лицензии и hashes.
- Extra `finetune` (Torch, Transformers, datasets и др.) не нужен и не должен устанавливаться в runtime.
- Dev/demo web-зависимости не нужны для CLI, кроме miniaudio как аудио-декодера; желательно отделить его от полного web extra.

### 11. Есть ли готовая телеметрия?

В коде T-one нет найденных вызовов telemetry, Sentry, внешнего логирования или проверки обновлений. Однако зависимость Hugging Face Hub имеет сетевые возможности, а demo загружает ресурсы CDN. В прототипе telemetry-disable переменные и deny egress применяются независимо от результата статического поиска.

### 12. Требования к CPU, RAM, GPU, ОС и диску

- upstream описывает pipeline как CPU-only;
- README требует Python >=3.9 и Linux/macOS, для Windows рекомендует Docker/WSL из-за KenLM;
- для demo upstream рекомендует минимум 4 CPU и 8 ГБ RAM;
- точный minimum RAM не опубликован и не измерен;
- веса beam-варианта занимают примерно 5,61 ГБ без окружения и кэшей; ONNX-only greedy — около 144 МБ весов;
- GPU для обычного Python pipeline не используется; опубликованные GPU-цифры относятся к отдельному TensorRT/Triton сценарию.

Текущая тестовая машина: Intel Core i5 1,6 ГГц, 2 ядра, 8 ГБ RAM, macOS 14.1.1, без доступного `ffmpeg`; системный Python 3.8.1 ниже требования. Для разработки доступен отдельный Python 3.12.13. Машина ниже рекомендации по CPU, поэтому результаты нельзя переносить на production sizing.

### 13. Какие форматы аудио поддерживаются?

Upstream README заявляет `.wav`, `.mp3`, `.flac`, `.ogg`. Их `read_audio()` использует `miniaudio.decode_file()`, сводит каналы в mono и ресемплирует в signed 16-bit 8 кГц (`tone/demo/read_audio.py:21-51`). Обвязка проекта добавляет `.aac` ADTS через локальный PyAV 18.0.0, также сводя в mono signed 16-bit 8 кГц. Синтетический AAC и фактический AAC v2 LC декодированы локально; полная матрица профилей AAC не заявляется.

### 14. Требуется ли FFmpeg?

Для WAV/MP3/FLAC/OGG — нет: используется miniaudio. Для запрошенного AAC добавлен optional PyAV wheel с бундлом FFmpeg. Runtime открывает только ранее проверенный локальный regular-file path в формате AAC, не принимает URL и не скачивает кодеки.

### 15. Поддерживаются ли длинные аудиофайлы?

Потоковая архитектура обрабатывает 300-мс chunks и сохраняет state. `forward_offline()` также режет произвольный одномерный массив на chunks, но `read_audio()` сначала декодирует весь файл в RAM. Явного лимита длительности и backpressure нет. Утверждение model card о длинных файлах правдоподобно по архитектуре, но максимальная длительность не протестирована.

### 16. Возвращаются ли таймкоды?

Да, Python API возвращает `TextPhrase(text, start_time, end_time)` с округлением до 0,01 с (`tone/pipeline.py:18-31,139-165`). Это **таймкоды фраз**, а не слов. Model card заявляет word-level timestamps, но проверенный pipeline их не возвращает; документация расходится с API.

### 17. Есть ли потоковое распознавание?

Да. `forward()` принимает ровно 2400 samples (300 мс при 8 кГц), возвращает новые завершённые фразы и state. `finalize()` сбрасывает остаток. Живой streaming не входит в наш MVP.

### 18. Ограничения одновременных задач

Явного лимита, очереди, блокировки и backpressure в T-one нет. Demo хранит один singleton pipeline, а state — на соединении. Проверенный высокоуровневый `pipeline.forward()` принимает один chunk формы `(2400,)`, хотя низкоуровневая ONNX-обёртка умеет batch. Без нагрузочного теста нельзя считать параллельные вызовы безопасными или выбрать число воркеров. Наш первый этап — один процесс/одна задача; дальнейшая параллельность ограничивается очередью и измерениями.

## Риски Docker/demo

- готовый Docker Hub image не проанализирован послойно и не используется;
- upstream Docker build зависит от непроверенного удалённого installer script и mutable base tags;
- demo автоматически скачивает модель при неверной конфигурации;
- web UI загружает сторонний JavaScript из CDN, что недопустимо для страницы с микрофонным аудио в закрытом контуре;
- demo не является надёжной очередью: нет идемпотентности, retry, durable state и лимитов задач;
- CORS-конфигурация сейчас false по умолчанию, но аутентификации/авторизации нет.

## Что ещё не подтверждено

- успешная установка зафиксированных native wheels на целевой промышленной ОС;
- полный SBOM, license notices и CVE scan;
- фактический RSS/CPU/RTF и загрузка 5,46-ГБ KenLM;
- качество greedy против beam search на согласованном наборе;
- отсутствие DNS/egress при локальном runtime;
- корректность всех заявленных аудиоформатов и длинных файлов;
- происхождение обучающих данных не аудитировалось; model card указывает преимущественно internal и pseudo-labeled данные, что требует отдельной governance-оценки при необходимости.

## Решение по результатам аудита

Критического лицензионного или архитектурного запрета на контролируемый локальный MVP не обнаружено. T-one остаётся основным кандидатом, но допуск условный: только `from_local`, зафиксированная revision/checksum, собственный CLI без web demo, deny egress и последующие runtime-тесты. Whisper.cpp пока не активируется.
