# Отчёт о готовности локального транскрибатора к пилоту

Дата среза: 2026-08-14.

## Резюме

Проект реализует локальную транскрибацию русской речи без облачного ASR: аудиофайл попадает в устойчивую SQLite-очередь, обрабатывается заранее подготовленной локальной моделью и сохраняется вместе с машинным JSON `1.1` и читаемым Markdown. Основной quality-путь на проверенном Windows/NVIDIA-хосте — `whisper.cpp` с Whisper large-v3; T-one/greedy используется как CPU fallback.

Текущий результат достаточен для контролируемой демонстрации на открытых или искусственных данных. Он не является допуском к обработке корпоративных звонков и не доказывает промышленное качество на телефонных диалогах.

## Что входит в пилот

- локальная обработка WAV, MP3, FLAC, OGG и AAC ADTS;
- безопасный `call_id` из имени файла;
- одиночный CLI и фоновый worker с SQLite-очередью;
- папка `data/calls/{call_id}/` с исходным аудио, `{call_id}.json` и `{call_id}.md`;
- схема результата `1.1`, исходный `raw_text`, очищенный `text` и сегменты с таймкодами;
- детерминированная постобработка и локальный словарь без LLM;
- технические логи без текста записи;
- нейтральный файловый и loopback-only HTTP-контракт для будущей CRM-интеграции.

В пилот не входят суммаризация, LLM-анализ, оценка эмоций или сотрудников, идентификация личности, сложный UI, дообучение и CRM-специфичная production-интеграция.

Source-поставка собирается `scripts/build_pilot_archive.py`: ZIP детерминирован, содержит `RELEASE_MANIFEST.json` с SHA-256 каждого файла и не включает локальные аудио, результаты, логи, окружения или веса. Модели подготавливаются отдельной проверяемой staging-фазой.

## Подтверждённые проверки

### Функциональность

- локальные модели и runtime идентифицируются manifests и контрольными суммами;
- результат публикуется атомарно, исходное аудио не перекодируется и не перезаписывается;
- очередь проверена на уникальность, lease/retry и восстановление;
- JSON `1.1` содержит модель/revision, для Whisper — VAD revision/SHA-256/порог, длительность, processing time, RTF, текст, raw ASR, сегменты и структурированную ошибку;
- Markdown содержит ссылку на аудио, сведения о модели, текст, фрагменты с таймкодами и предупреждение о проверке критичных данных.

### Качество на FLEURS

Использована локально сохранённая выборка `google/fleurs`, конфигурация `ru_ru/test`, лицензия CC-BY-4.0: шесть файлов подготовленного чтения, три женских и три мужских голоса, суммарно 84,96 с и 135 нормализованных слов эталона.

Аудио, эталоны и evaluation JSON исключены из Git вместе с прочими тестовыми данными. Локальный `data/output/pilot-acceptance` самодостаточен: manifest использует только внутренние пути, report фиксирует SHA-256/размер каждого входа и результата, а `ATTRIBUTION.md` содержит FLEURS/CC-BY-4.0 attribution и описание изменений. Передаваемый ZIP с полным inventory собирается отдельно командой `python scripts/build_pilot_evidence.py`; одних чисел в этом отчёте недостаточно для независимого пересчёта.

| Движок | Режим | Ошибки / слова | Micro WER | Macro WER |
|---|---|---:|---:|---:|
| Whisper large-v3 | `whisper.cpp`, beam search | 4 / 135 | 2,96% | 2,22% |
| T-one | greedy | 10 / 135 | 7,41% | 6,57% |

Во всех ошибках этой выборки зафиксированы замены; удалений и вставок нет. Micro WER рассчитан по объединённому числу ошибок и слов, macro WER — как среднее WER шести файлов. Нормализация не оценивает регистр и пунктуацию.

Результат подтверждает преимущество Whisper на этой малой выборке читаемой естественной речи. Он не переносится автоматически на звонки: в FLEURS нет двухстороннего телефонного диалога, телефонного канала, перебиваний и контролируемых уровней шума.

### Повторная проверка после VAD и валидации таймкодов

14 августа 2026 года Whisper повторно прогнан самым последним кодом с обязательным локальным Silero VAD на тех же шести FLEURS-файлах и четырёх детерминированных неречевых сигналах по 10 секунд: цифровая тишина, тихий и громкий белый шум, чистый тон 440 Гц.

- FLEURS: raw/final micro-WER `2,96%`, macro-WER `2,22%`, то есть 4/135 ошибок — без ухудшения относительно исходного прогона;
- raw/final micro-CER `0,53%`, macro-CER `0,39%`;
- все четыре неречевых файла: 0 распознанных слов и 0 сегментов;
- нарушения `0 <= start <= end <= duration` и монотонности: 0;
- дефект `,.` в новых результатах не воспроизвёлся.

До VAD на тех же классах сигналов Whisper возвращал 7 слов на тишине, по 2 слова на двух уровнях шума и 3 слова на тоне. Агрегированный отчёт строится `scripts/run_pilot_benchmark.py` без включения текстов в report; он фиксирует SHA-256 и размер каждого transcript/reference и, если указан, аудио, а также hash исходного дерева. Это закрывает найденную регрессию, но не доказывает отсутствие false negative на очень тихой телефонной речи.

### Критичные реквизиты

На искусственном файле `1001.wav` Whisper сохранил БИК, ИНН, НКЦ, сумму и дату, но преобразовал произнесённое «четыре ноля и один» в `4001`. Новый opt-in evaluator критичных полей с явными допустимыми вариантами дал 1/2: БИК найден, исходная фраза счёта — нет. Manifest фиксирует этот diagnostic-аудиофайл, эталон и результат отдельными SHA-256, но намеренно не смешивает их числовое форматирование с FLEURS WER. Поэтому WER недостаточен для бизнес-допуска: суммы, даты, имена, отрицания и реквизиты требуют согласованной exact-match проверки и сверки по аудио.

## Неподтверждённые свойства

- качество на реальных телефонных диалогах, шумах, быстрой речи и перебиваниях;
- допустимая точность сумм, дат, имён и реквизитов;
- точность границ сегментов и пригодность таймкодов для бизнес-сценария;
- поведение на длинной тишине, тихой речи и ложных срабатываниях VAD;
- production throughput, параллельность и sizing на целевом оборудовании;
- полный runtime egress-аудит, SBOM/CVE и юридический review точной поставки;
- production transport, аутентификация, TLS, ACL и политика хранения CRM.

## Acceptance gates

Статус `не пройден` означает, что свойство нельзя обещать на демонстрации или использовать как основание для корпоративного допуска.

| Gate | Условие прохождения | Текущий статус |
|---|---|---|
| Windows acceptance | Чистый архив на целевом Windows-хосте проходит первый запуск, повторный offline-запуск и создаёт валидные JSON/Markdown на контрольной записи | Не пройден в составе финальной поставки |
| VAD / неречевые сигналы | Детерминированные тишина/шум/тон дают 0 слов, а FLEURS не ухудшается | Пройдено на regression-наборе; тихая телефонная речь ещё не проверена |
| Валидность таймкодов | Все опубликованные сегменты finite, монотонны и лежат внутри аудио | Пройдено кодом и на 11 acceptance-файлах; точность границ ещё не размечена |
| Критичные поля | На отдельном наборе согласован и достигнут exact-match порог для сумм, дат, имён, отрицаний и реквизитов | Не пройден |
| Телефонное качество | Проверен лицензированный или записанный с согласием набор диалогов с телефонной полосой, шумом, скоростью и перебиваниями | Не пройден |
| Security | После staging подтверждены OS-level deny-all egress для Python и нативного ASR, наблюдение DNS/соединений, hashes и review поставки | Не пройден |
| Производительность | На целевом хосте измерены sustained RTF, CPU/GPU/RAM, ошибки и обоснованная параллельность | Не пройден |

## Рекомендуемый сценарий демонстрации

1. Использовать заранее подготовленный Windows/NVIDIA-хост и только открытые либо искусственные записи.
2. Запустить транскрибатор, положить один файл с безопасным ASCII-именем в `data/input`.
3. Открыть `data/calls/{call_id}/{call_id}.md`, показать переход к исходному аудио, полный текст и фрагменты.
4. Открыть JSON `1.1`, показать идентификатор модели/revision, `raw_text`, очищенный `text`, processing time и RTF.
5. Показать таблицу FLEURS и отдельно ошибку `4001` как пример честного ограничения.
6. Завершить демонстрацию списком acceptance gates, не выдавая пилот за production-сервис.

## Решение по следующему этапу

Рациональный следующий этап — закрыть acceptance gates на целевом Windows-хосте и небольшом согласованном наборе телефонных сценариев. Расширять продукт LLM, суммаризацией или сложным UI до этих измерений не требуется.
