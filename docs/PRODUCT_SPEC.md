# Product specification

## Бизнес-проблема

Телефонные разговоры хранятся в корпоративной CRM как аудиофайлы, но их содержание нельзя быстро искать или показывать как текст. Передача таких данных внешнему провайдеру недопустима.

## Цель

Создать автономный сервис, который после завершения звонка находит аудиофайл, извлекает `call_id`, локально распознаёт русскую телефонную речь и сохраняет версионированный JSON под тем же идентификатором.

Минимальный доказуемый сценарий:

```text
1234.wav -> локальный ASR -> 1234.json
```

## Пользователи

- оператор сервиса или администратор, запускающий обработку;
- будущая команда CRM, читающая результат по зафиксированному контракту;
- специалисты ИБ, проверяющие происхождение компонентов и автономность.

## Вход

- аудиофайл завершённого звонка;
- на MVP `call_id` берётся из безопасного имени файла;
- ожидаемый язык — русский;
- фактические контейнеры, кодеки, частота, число каналов и ограничения длительности пока неизвестны.

## Выход

UTF-8 JSON со схемой `1.0`: `call_id`, статус, имя источника, язык, длительность, время обработки, RTF, идентификатор и локальный путь модели, полный текст, сегменты с таймкодами, временные метки и структурированная ошибка. Необязательный TXT предназначен только для просмотра человеком.

## Минимальная первая версия

1. Ручная CLI-обработка одного WAV и, если движок надёжно поддерживает, одного сжатого формата.
2. Строгая локальная загрузка заранее подготовленной модели из `models/`.
3. Отсутствие загрузок и внешних запросов во время инференса.
4. Явные ошибки, измерение длительности и RTF.
5. Автоматические тесты контракта и обработки ошибок без корпоративных данных.
6. Один успешный тест на искусственном русском аудио.

Очередь и наблюдение за каталогом начинаются только после успешного одиночного теста.

## Критерии успешной транскрибации

- входной файл не изменён;
- результат имеет корректную схему и тот же `call_id`;
- модель действительно загружена с локального пути;
- после первоначальной подготовки тот же тест проходит без сети;
- фактический текст сравнен с эталоном, ошибки приведены примерами;
- измерены длительность, время обработки и RTF;
- в логах отсутствует полный текст звонка.

Числовой порог WER и допустимые ошибки в реквизитах должен согласовать владелец продукта. До этого нельзя объявлять качество приемлемым только по субъективной оценке.

## Вне текущего проекта

Суммаризация, LLM-анализ, эмоции, контроль качества сотрудников, биометрия и идентификация личности, CRM-интеграция, сложный UI, обучение/дообучение, живая транскрибация звонка и автоматическое принятие бизнес-решений.
