# Журнал архитектурных решений

## ADR-001

**Решение:** T-one проверяется как основной кандидат; whisper.cpp остаётся резервом.  
**Дата:** 2026-08-09  
**Статус:** принято для этапа исследования  
**Контекст:** нужен локальный ASR русской телефонной речи; обучение модели с нуля запрещено.  
**Выбранный вариант:** сначала проверить официальный T-one и его предобученные веса.  
**Альтернативы:** whisper.cpp; другие локальные ASR не рассматриваются до появления причины отказаться от T-one.  
**Причина:** T-one заявлен как потоковая модель, специализированная для русской телефонии, и прямо указан заказчиком как основной кандидат.  
**Последствия:** прототип не должен преждевременно связывать доменную логику с API модели; нужен адаптер и проверка локальной загрузки.

## ADR-002

**Решение:** разделить подготовку артефактов и runtime-инференс.  
**Дата:** 2026-08-09  
**Статус:** принято  
**Контекст:** зависимости и веса можно получить первоначально, но после установки сервис обязан работать без интернета.  
**Выбранный вариант:** отдельная документированная staging-процедура формирует локальный каталог модели и манифест контрольных сумм; runtime не скачивает ничего.  
**Альтернативы:** разрешить библиотеке заполнять кэш при первом звонке.  
**Причина:** первый runtime-вызов с автоскачиванием нарушает автономность и затрудняет воспроизводимость.  
**Последствия:** CLI завершится явной ошибкой при отсутствии локальной модели; автоматического fallback не будет.

## ADR-003

**Решение:** очередь и watcher реализуются только после успешной обработки одного искусственного файла.  
**Дата:** 2026-08-09  
**Статус:** принято  
**Контекст:** преждевременная очередь усложнит диагностику модели, качества и автономности.  
**Выбранный вариант:** сначала ручной CLI и стабильный JSON-контракт.  
**Альтернативы:** сразу создать демон и API.  
**Причина:** соответствует критическому пути и ограничивает объём первой проверки.  
**Последствия:** фоновые режимы остаются запланированными, но не считаются частью первого доказательства.

## ADR-004

**Решение:** использовать только локальный конструктор T-one и собственный CLI; upstream web demo/готовый Docker-образ исключить.  
**Дата:** 2026-08-09  
**Статус:** принято после статического аудита  
**Контекст:** upstream предоставляет `from_local`, но demo при отсутствии переменной окружения вызывает Hugging Face, а браузер загружает JavaScript/CSS с внешнего CDN. Docker build также скачивает installer и веса.  
**Выбранный вариант:** проверенные локальные артефакты, `StreamingCTCPipeline.from_local`, offline/telemetry-disable flags, собственная CLI-обвязка без web-зависимостей.  
**Альтернативы:** официальный demo, Docker Hub image, `from_hugging_face()` в runtime.  
**Причина:** локальный API минимален, проверяем и не требует сети в видимом коде.  
**Последствия:** нужно отдельно подготовить модель и зависимости; отсутствие файлов является ошибкой; сеть всё равно блокируется на уровне ОС.

## ADR-005

**Решение:** начать фактический тест с одной задачи и не выбирать параллельность до измерений.  
**Дата:** 2026-08-09  
**Статус:** принято  
**Контекст:** текущая машина имеет 2 CPU/8 ГБ, а upstream рекомендует 4 CPU/8 ГБ; `kenlm.bin` занимает около 5,46 ГБ.  
**Выбранный вариант:** одиночный инференс, измерение RSS/RTF; очередь и воркеры позже.  
**Альтернативы:** сразу параллельные тесты или Triton/TensorRT.  
**Причина:** не допустить OOM и не смешивать проверку функциональности с масштабированием.  
**Последствия:** данные текущего ноутбука не являются production sizing; beam search может потребовать более подходящую машину.

## ADR-006

**Решение:** использовать SQLite/WAL, транзакционный claim и продлеваемый lease для локальной очереди.  
**Дата:** 2026-08-09  
**Статус:** принято и реализовано  
**Контекст:** после успешного одиночного теста требуются восстановление после перезапуска, запрет двойной обработки и ограниченные retry без внешней инфраструктуры.  
**Выбранный вариант:** одна SQLite-база, статусы `new/queued/processing/completed/failed`, стабильность size/mtime, `BEGIN IMMEDIATE`, worker UUID, heartbeat и exponential backoff.  
**Альтернативы:** файлы-маркеры; Redis/RabbitMQ; сразу несколько параллельных воркеров.  
**Причина:** SQLite локален, транзакционен, не требует сетевого сервиса и достаточен для MVP.  
**Последствия:** база должна находиться на файловой системе с корректной SQLite locking semantics; NFS/SMB требуют отдельной проверки. Масштабирование за пределы одного узла потребует нового ADR.

## ADR-007

**Решение:** первый фактический тест выполнить с greedy decoder, не выдавая его качество за beam-search качество T-one.  
**Дата:** 2026-08-09  
**Статус:** временно принято  
**Контекст:** `model.onnx` занимает 144 МБ, `kenlm.bin` — 5 463 477 004 байта; на тестовом хосте 8 ГБ RAM и около 12 ГБ свободного диска.  
**Выбранный вариант:** доказать локальный pipeline на greedy, сохранить параметр `--decoder beam_search` и строгую проверку KenLM.  
**Альтернативы:** сразу скачать/загрузить KenLM; перейти на whisper.cpp.  
**Причина:** ограничить риск исчерпания диска/RAM и сначала проверить интеграционный контракт.  
**Последствия:** WER `0,1930` синтетического теста относится только к greedy; окончательное решение по T-one ожидает beam-search и естественный набор.

## ADR-008

**Решение:** для проверенного Windows MVP использовать hash-pinned CPython 3.11 wheelhouse и greedy без Python binding KenLM; исходящий трафик runtime блокировать отдельным firewall-правилом.  
**Дата:** 2026-08-09  
**Статус:** принято и реализовано для Windows greedy  
**Контекст:** официального Windows wheel `kenlm==0.3.0` нет, Visual C++ build tools на хосте отсутствуют, но upstream `tone==0.1.0` объявляет KenLM обязательным и импортирует `pyctcdecode` даже для фактически независимого greedy decoder-а. Непроверенный бинарник или большая локальная toolchain увеличат риск цепочки поставки.  
**Выбранный вариант:** зафиксировать Windows wheels и SHA-256 в `requirements/windows-greedy.txt`, собрать неизменённый официальный T-one wheel локально, установить его с `--no-deps`, оставить строгую проверку отсутствующего `kenlm.bin` для beam search и подавить только ожидаемое предупреждение PyCTCDecode в greedy-режиме. После staging применяется `security/windows-deny-network.ps1`.  
**Альтернативы:** собирать KenLM из sdist; брать неофициальный Windows wheel; патчить upstream packaging/импорты; перейти на whisper.cpp.  
**Причина:** минимальный проверяемый путь даёт рабочий быстрый локальный greedy без непроверенных бинарников и не меняет код аудита T-one.  
**Последствия:** `pip check` сообщает известное отсутствие `tone -> kenlm`; это не допускается выдавать за готовый beam runtime. Для beam search потребуется проверенная сборка KenLM, локальный `kenlm.bin` и новый тест. Firewall-скрипт требует административных прав и не был применён в текущей ограниченной сессии.

## ADR-009

**Решение:** Windows worker измеряет CPU через `time.process_time()`, а недоступный peak RSS явно печатает как `unavailable`; новую runtime-зависимость только ради метрики не добавлять.  
**Дата:** 2026-08-09  
**Статус:** принято и реализовано  
**Контекст:** `worker_cli.py` безусловно импортировал Unix-only модуль `resource`, из-за чего worker не запускался на Windows.  
**Выбранный вариант:** условный импорт `resource`; Linux/macOS сохраняют прежние CPU/RSS-метрики, Windows сохраняет wall/CPU и честно не заявляет RSS.  
**Альтернативы:** добавить `psutil`; реализовать Windows Process Status API через `ctypes`; отказаться от Windows worker.  
**Причина:** метрика памяти не должна блокировать обработку и не оправдывает новую зависимость до performance-этапа.  
**Последствия:** для Windows capacity planning peak RSS нужно отдельно измерить штатным мониторингом ОС или после обоснованного добавления проверенной зависимости.

## ADR-010

**Решение:** переносить проект между Windows и macOS через приватный GitHub-репозиторий только с исходным кодом и безопасными manifests.  
**Дата:** 2026-08-10  
**Статус:** принято и реализовано  
**Контекст:** владельцу нужен переносимый репозиторий, но модель, аудио, транскрипции, логи, окружения и staging-кэши нельзя публиковать или смешивать с исходниками.  
**Выбранный вариант:** приватный `gurulow1/local-call-transcriber`; `.gitignore` исключает `models/*`, фактические `data/*`, `logs/*`, `.venv/`, `.poetry-cache/` и `third_party/`. На новом Mac зависимости, официальный pinned checkout T-one и модель подготавливаются заново по `docs/INSTALLATION.md`.  
**Альтернативы:** публичный репозиторий; Git LFS для модели/аудио; архив всей рабочей папки; включение vendored T-one.  
**Причина:** минимизировать риск раскрытия данных и не превращать GitHub в хранилище тяжёлых или приватных runtime-артефактов.  
**Последствия:** одного `git clone` недостаточно для инференса; на каждом хосте нужен контролируемый staging и локальная проверка весов. Доступ к приватному репозиторию требуется настроить отдельно на Mac.
