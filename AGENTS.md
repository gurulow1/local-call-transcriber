# Постоянные правила проекта

Эти правила действуют для всех последующих сессий и для всего дерева `transcriber/`.

1. Сервис автономный и локальный. Внешние API и облачные ASR запрещены.
2. Аудио, транскрипции и метаданные нельзя отправлять за пределы корпоративного контура.
3. В тестовой среде запрещены реальные корпоративные данные. Допустимы только искусственные, самостоятельно записанные или открытые тестовые данные с проверенной лицензией.
4. Во время обработки модель загружается только с локального диска. Автоматическая загрузка весов запрещена.
5. Сначала выполняются анализ, фиксация требований и проверка рисков, затем реализация.
6. Не добавлять функции вне текущего этапа: без суммаризации, LLM-анализа, эмоций, контроля сотрудников, идентификации личности, интеграции с CRM, сложного UI и дообучения.
7. Не менять архитектуру молча. Каждое архитектурное изменение фиксировать в `docs/DECISIONS.md`.
8. После изменения кода запускать применимые тесты. Если тест невозможен, явно зафиксировать причину.
9. При изменении поведения обновлять документацию и контракт.
10. Отделять подтверждённые факты от предположений. Неизвестные сведения записывать в `docs/OPEN_QUESTIONS.md`.
11. Не придумывать устройство CRM, корпоративной сети и инфраструктуры.
12. Исходные аудиофайлы не изменять и не удалять.
13. Логи не должны содержать полный текст звонка или фрагменты аудио.
14. Новые зависимости сначала проверять по назначению, лицензии, источнику и сетевому поведению; версии фиксировать.
15. Не считать open source доказательством безопасности. Нужны анализ кода, конфигурация, контроль целостности и сетевые ограничения.
